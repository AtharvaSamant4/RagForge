# Browser QA

Real Playwright Chromium workflows run against the independent `ragforge-m2` Docker deployment. The dashboard, API, PostgreSQL/pgvector, ingestion worker, semantic model and widget endpoints are real; application APIs and inference are not mocked. The embedding website is a temporary HTTP server on loopback port 4020, so Chromium can validate actual cross-origin widget loading and `frame-ancestors` policy.

The final executed run and timings are recorded in [qa/browser-results.json](qa/browser-results.json). Desktop viewport: 1440×1000. Mobile viewport: 390×844 with touch/mobile emulation. This is Chromium viewport coverage, not a claim of testing every browser or physical device.

## Interaction coverage

Both viewport workflows exercise registration, project creation, real PDF upload, visible queued/processing/ready state, extracted chunk preview and Escape dismissal, unsupported upload errors, chat answers, citation expansion, retrieved passages, unsupported-question refusal, pipeline settings, controlled reindex completion, all three retrieval comparisons, manually labeled evaluation and measured results, API key creation and an authenticated query using the newly created key, widget publication/appearance settings, an actual embedded widget question, revocation, document deletion, disabled empty-index chat, project deletion, logout, login and logout again.

Each screenshot step asserts there is no page-level horizontal overflow. The test collects uncaught page exceptions and requires none. Successful workflows delete their fixture projects; failed exploratory runs may leave their own disposable QA fixtures, never data in the original `ragforge` deployment.

## Observed issues and fixes

* Mobile navigation previously hid routes behind horizontal scrolling. A labeled native section selector now exposes every route.
* Mobile document rows hid size/actions offscreen. They now render as cards with visible status, chunk count, size and deletion control.
* Small status, citation and message text was enlarged. Long model names/revisions wrap within the panel.
* Widget settings could accept an edit before initial loading finished, then overwrite it with a late GET response. The form now waits for its loading state.
* The pipeline lifecycle message could continue requesting a rebuild after the model panel showed ready. Both views now use the polled server compatibility/reindex result.
* PDF soft wraps produced partial sentence excerpts. Sentence selection now preserves complete soft-wrapped source sentences and exact citation substrings.

Exploratory test-harness failures were also corrected: Next.js adds its own alert region, document navigation includes a count, and a request-intercepted synthetic host triggers Chromium's loopback-network protection. Tests now target the intended alert/navigation controls and use a real loopback HTTP embedding host. Browser security protections were not disabled. Full-page screenshots reset document scroll to avoid misplaced fixed-sidebar capture artifacts.

## Reproduce

Start the isolated stack as documented in README.md, wait for/prefetch the model, then:

```sh
cd frontend
npm ci
npx playwright install chromium
npm run test:e2e
```

Set `QA_BASE_URL` to the dashboard origin if using a different port. The configured `APP_ORIGINS` must match. Port 4020 must be free. Traces, failure screenshots, HTML and JSON reports are written under `artifacts/browser`; successful representative captures are written under `docs/qa/screenshots`. The CI workflow provisions Chromium and runs the same suite against Docker.
